## What the runs changed in the skill

1. **Inline codemods.** A change one deterministic command completes is not model work.
   The lead's own run-2 reasoning showed the old gate contradicted itself.
2. **Jev trigger.** Run eligible recipes in shadow mode even when triaging inline. Without
   this, a capable lead never called Jev. With it, Jev was called in every eligible run.
3. **Off-family review when Claude builds.** Add a read-only Codex or Grok review, or log
   why not. In run 4 that review caught two real test gaps the Claude verifier passed.

## What the runs changed in the harness or grader (not the skill)

- `/skill-name` does not load a skill in `claude -p`, so the prompt now invokes it
  through the Skill tool, and check 0.1 verifies it loaded.
- The T4 answer key was wrong: "tax before discount" has no numeric effect, and the lead
  proved it.
- Shell edits (`perl -pi`, `sed -i`) now count as lead edits; paths merely mentioned in a
  command no longer do.
- 5.3 accepts plain-language explanations.

## Remaining variability (one run per scenario is evidence, not a rate)

- The FAST-vs-WORKHORSE choice for T2 varied (Haiku in run 3, Sonnet in run 5, with a
  logged reason).
- Leads preferred in-harness Claude workers over pre-approved Grok and Codex for small
  tickets, citing transport overhead (3.2b WARN). **This is no longer policy.** After the
  user's review (2026-09-24), the routing card makes "transport overhead" a forbidden
  deviation reason, and scenarios T8–T13 test for it. See the run-6 results below.
